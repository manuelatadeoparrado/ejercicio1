# Criterios de desarrollo

## Principios generales
- Priorizar soluciones simples, legibles y fáciles de mantener.
- Mantener HTML, CSS y JavaScript separados en sus archivos correspondientes.
- Evitar dependencias externas salvo que exista una necesidad justificada.
- No cambiar funcionalidades existentes sin comprobar el impacto.

## HTML
- Usar HTML semántico y una estructura válida.
- Mantener el atributo `lang` adecuado al idioma del contenido.
- Incluir metadatos básicos y etiquetas accesibles.
- Asociar controles y textos de forma comprensible.

## CSS
- Mantener los estilos en `style.css`.
- Favorecer reglas claras y reutilizables.
- Comprobar que la página se pueda utilizar en pantallas pequeñas y grandes.
- Cuidar contraste, legibilidad y estados visibles de interacción.

## JavaScript
- Mantener la lógica en `script.js`.
- Usar nombres descriptivos.
- Evitar errores cuando un elemento del DOM no exista.
- Preferir soluciones sencillas y compatibles con navegadores actuales.

## Cambios en el repositorio
- Antes de editar, leer el contenido actual del archivo.
- Hacer cambios acotados y coherentes con el objetivo solicitado.
- No sobrescribir trabajo existente sin revisarlo.
- Usar mensajes de commit claros y descriptivos.
- Verificar el resultado cuando sea posible.

## Decisiones aún no especificadas
Las preferencias visuales, los navegadores objetivo, los requisitos de accesibilidad y cualquier restricción académica o técnica deben confirmarse antes de tratarlos como requisitos obligatorios.
